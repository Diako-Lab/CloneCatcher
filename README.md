## Overview

CloneCatcher reconstructs T cell receptor repertoires, identifies clonotypes that expand within or between conditions, and links expanded clones to candidate neoantigens by shared-specificity clustering.

Two input modalities are handled by interchangeable frontends that emit the same clonotype schema, so a bulk co-culture experiment and a 5' single-cell dataset are analyzed by identical downstream code:

| Mode | Input | Reconstruction |
|------|-------|----------------|
| `bulk` | 5' RACE TCR libraries (FASTQ) | TRUST4 |
| `single_cell` | 10x 5' paired GEX + VDJ-T | `cellranger multi` |

In `single_cell` mode, clonotypes are additionally resolved to individual cells and joined onto [ClusterCatcher](https://github.com/JakeLehle/ClusterCatcher) output, giving per-cell receptor identity alongside cell type annotation, mutational signature exposure, and copy number burden.

### Pipeline Family

CloneCatcher is the third stage in a chain of pipelines that share conventions and hand off cleanly:

```
SRAscraper ──> ClusterCatcher ──> CloneCatcher
 (download)     (GEX: annotation,   (VDJ: repertoire,
                 mutations,          expansion,
                 signatures)         specificity)
```

Each takes a config file generated by its own CLI and writes to a project-specific working directory. The repository holds code only.

### Key Features

- **Dual frontend**: one pipeline for bulk and single-cell TCR data
- **Two output levels**: clonotypes per sample in both modes, plus per cell in `single_cell`
- **Namespace enforcement**: every barcode merge asserts a join rate rather than silently returning empty
- **Modular design**: enable only the stages you need
- **Reproducible**: Snakemake with per-stage conda environments
- **Publication-ready plots**: 300 DPI, PDF and PNG

## Requirements

### System Requirements

- **Linux** (tested on Ubuntu 20.04+, CentOS 7+)
- **Python** >= 3.9
- **Memory**: 32GB RAM recommended (TRUST4 assembly is the peak)
- **Storage**: ~10GB per bulk library; negligible for `single_cell`, where CellRanger output already exists

### External Software

| Software | Version | Purpose | Mode |
|----------|---------|---------|------|
| **Snakemake** | >=7.0 | Pipeline orchestration | Both |
| **TRUST4** | >=1.0.13 | Repertoire reconstruction | `bulk` |
| **Cell Ranger** | >=7.0 | VDJ assembly (run upstream) | `single_cell` |
| **R** | >=4.2 | Immunarch backend | Both |

TRUST4 is vendored under `external/`, following the same pattern as SComatic and CytoTRACE2 in ClusterCatcher.

### Upstream Requirements

`single_cell` mode requires a completed ClusterCatcher run over the same samples, and a `cellranger multi` run with a VDJ-T library.

## Installation

### 1. Clone the Repository

```bash
git clone https://github.com/JakeLehle/CloneCatcher.git
cd CloneCatcher
```

### 2. Create Conda Environment

```bash
mamba env create -f environment.yml
conda activate CloneCatcher
```

### 3. Install CloneCatcher Package

```bash
pip install -e .
```

### 4. Build TRUST4 (bulk mode only)

```bash
cd external/TRUST4 && make && cd ../..
./external/TRUST4/run-trust4 --version
```

### 5. Download the IMGT Reference (bulk mode only)

```bash
./external/TRUST4/BuildImgtAnnot.pl Homo_sapiens > resources/IMGT+C.fa
```

### 6. (Optional) Fetch Specificity Databases

```bash
CloneCatcher fetch-databases --output-dir resources/
```

Downloads VDJdb and McPAS-TCR. Skip if `specificity.reference_dbs` is empty.

## Quick Start

As with ClusterCatcher, all analysis is written to a project-specific working directory outside the repository. The CloneCatcher directory holds code only.

### Step 1: Prepare Sample Information

**`single_cell` mode** reads samples from the upstream ClusterCatcher run, so no sample sheet is needed:

```bash
CloneCatcher inspect-barcodes --run-dir /path/to/clustercatcher_results
```

Run this first. It reports the barcode namespace, confirms what `sample_id` resolves to, and measures the VDJ join rate so `min_join_rate` is set from data rather than guessed.

**`bulk` mode** takes a CSV:

```csv
sample_id,fastq_r1,fastq_r2,condition,donor
D1_MUT_A,/path/D1_MUT_A_R1.fq.gz,/path/D1_MUT_A_R2.fq.gz,mutant,DONOR1
D1_WT_A,/path/D1_WT_A_R1.fq.gz,/path/D1_WT_A_R2.fq.gz,wildtype,DONOR1
D1_EV_A,/path/D1_EV_A_R1.fq.gz,/path/D1_EV_A_R2.fq.gz,empty_vector,DONOR1
```

```bash
CloneCatcher sample-information --input samples.csv --output samples.pkl
```

### Step 2: Generate Configuration

```bash
# single_cell
python cli/create_config.py \
    --output-dir ./results_GSE226620 \
    --input-mode single_cell \
    --clustercatcher-run-dir /path/to/clustercatcher_results \
    --min-join-rate 0.40 \
    --threads 16

# bulk
python cli/create_config.py \
    --output-dir ./results_aim2 \
    --input-mode bulk \
    --sample-pickle samples.pkl \
    --imgt-reference resources/IMGT+C.fa \
    --contrast-group condition \
    --contrast-test mutant \
    --contrast-reference wildtype \
    --contrast-exclude empty_vector \
    --block-column donor \
    --threads 16
```

### Step 3: Run the Pipeline

```bash
cd snakemake_wrapper
snakemake --configfile ../results_GSE226620/config.yaml \
    --cores 16 \
    --use-conda
```

Or through the CLI:

```bash
CloneCatcher run-config --config ./results_GSE226620/config.yaml --cores 16
```

## Pipeline Modules

### Module 1a: TRUST4 Reconstruction (`bulk`)

**Script**: `snakemake_wrapper/scripts/trust4_reconstruct.py`

Assembles TCR contigs from 5' RACE libraries and calls clonotypes.

| Parameter | Default | Description |
|-----------|---------|-------------|
| `imgt_reference` | required | IMGT+C FASTA from `BuildImgtAnnot.pl` |
| `min_abundance` | `2` | Minimum read support for a clonotype |
| `chains` | `TRA,TRB` | Chains to retain |

**Outputs**: `tcr/trust4/{sample}/` plus a per-sample clonotype table.

---

### Module 1b: VDJ Parse (`single_cell`)

**Script**: `snakemake_wrapper/scripts/cellranger_vdj_parse.py`

Reads `filtered_contig_annotations.csv` and `clonotypes.csv` from the `cellranger multi` output. CellRanger has already performed assembly and clonotype calling, so this stage parses rather than reconstructs.

| Parameter | Default | Description |
|-----------|---------|-------------|
| `require_productive` | `true` | Drop non-productive contigs |
| `require_paired` | `false` | Keep orphan-chain cells, flagged `is_paired=false` |
| `min_umis` | `2` | Minimum UMI support per contig |

---

### Module 2: Barcode Namespace (`single_cell`)

**Script**: `snakemake_wrapper/scripts/barcode_namespace.py`

Promotes CellRanger's bare VDJ barcodes into ClusterCatcher's canonical namespace and asserts the join. See [Barcode Namespace](#barcode-namespace).

| Parameter | Default | Description |
|-----------|---------|-------------|
| `min_join_rate` | `0.40` | Floor for VDJ-to-GEX overlap; raises below this |
| `on_unmapped` | `drop` | `drop` or `raise` for VDJ cells absent from GEX |

**Outputs**: `tcr/clonotypes_by_cell.tsv`, `tcr/barcode_join_report.tsv`

---

### Module 3: Repertoire Statistics

**Script**: `snakemake_wrapper/scripts/repertoire_stats.py`

Wraps Immunarch for clonality, diversity, V/J usage, and repertoire overlap. The script is Python and shells out to R, following the pattern used for inferCNV in ClusterCatcher.

| Parameter | Default | Description |
|-----------|---------|-------------|
| `diversity_methods` | `chao1,shannon,gini` | Diversity indices |
| `top_n_clones` | `20` | Clones shown in abundance plots |

---

### Module 4: Expansion

**Script**: `snakemake_wrapper/scripts/expansion_test.py`

Clone frequencies are modeled with a beta-binomial, sequencing depth as an offset, Benjamini-Hochberg corrected at the configured FDR.

The stage behaves differently depending on whether a contrast is declared, because the two modalities ask different questions. With `contrast: null`, it reports per-sample expanded-clone calls and clonality with no hypothesis test, which is what a tumor dataset with no experimental arms supports. With a contrast declared, it runs the differential test between conditions within the blocking variable.

| Parameter | Default | Description |
|-----------|---------|-------------|
| `contrast` | `null` | Group column, test level, reference level, exclusions, blocking variable |
| `fdr` | `0.05` | Benjamini-Hochberg threshold |
| `expansion_threshold` | `0.01` | Within-sample frequency defining an expanded clone |

Clones expanding against an excluded condition are removed before test-versus-reference comparison.

---

### Module 5: Specificity

**Script**: `snakemake_wrapper/scripts/tcrdist_cluster.py`

tcrdist3 computes pairwise receptor distances and clusters receptors sharing specificity features. Clusters are scored against VDJdb and McPAS-TCR.

| Parameter | Default | Description |
|-----------|---------|-------------|
| `method` | `tcrdist3` | Distance metric |
| `radius` | `50` | tcrdist clustering radius |
| `reference_dbs` | `vdjdb,mcpas` | Databases for annotation |

These are prioritizations rather than demonstrations of binding. The ranked output is intended as input to experimental validation.

---

### Module 6: ClusterCatcher Integration (`single_cell`)

**Script**: `snakemake_wrapper/scripts/join_clustercatcher.py`

Adds clonotype identity, chain pairing, and expansion status to the ClusterCatcher AnnData `obs`, producing `adata_tcr.h5ad`.

Cell type, signature exposure, and copy number are read from ClusterCatcher at join time rather than copied into the flat clonotype tables. Those tables carry receptor identity only, so a ClusterCatcher rerun does not leave stale duplicates behind.

## Barcode Namespace

This is the highest-risk surface in `single_cell` mode, and it is enforced rather than assumed.

ClusterCatcher's canonical barcode is `{sample_id}_{cellranger_barcode}`, for example `HPV01_AAACCTGGTGAGGGTT-1`. CellRanger's VDJ output carries the bare form `AAACCTGGTGAGGGTT-1` with no sample identity. Promoting one to the other is the join every single-cell result depends on.

`sample_id` is whatever identifier the upstream ClusterCatcher run was configured with. It is often an SRA run accession, but it is not required to be, and it will not be when several sequencing runs belong to one sample, as with paired GEX and VDJ libraries. CloneCatcher reads it from the AnnData rather than deriving it from accessions or directory names. Run `inspect-barcodes` to see what it resolves to for a given run.

Three rules:

- **The CellRanger suffix is retained.** It is part of the barcode. CloneCatcher never synthesizes a suffix and never strips one.
- **Promotion prefixes `{sample_id}_` onto the barcode CellRanger wrote.** It does not rebuild the barcode from parts.
- **Every merge asserts a join rate.** A failed join is unknown data, never absent data. A zero-overlap merge raises with an example barcode from each side rather than returning empty.

A VDJ cell absent from the GEX matrix is legitimate, since VDJ libraries recover T cells that GEX QC drops. The expected join rate is therefore below 100%, which is why `min_join_rate` is configured per run and measured by `inspect-barcodes` rather than hardcoded. A low rate on a correct join is a finding worth inspecting. A zero rate is a bug by definition.

**ClusterCatcher runs from v1.0.2 through v1.4.2 carry barcodes in the form `{barcode}-{suffix}-{sample_id}`,** which joins to nothing. CloneCatcher refuses those inputs at the entry point. Run `repair_barcodes.py` on the ClusterCatcher run first.

## Configuration Reference

```yaml
# =============================================================================
# CloneCatcher Configuration
# =============================================================================

output_dir: "/path/to/results_GSE226620"
input_mode: "single_cell"          # single_cell | bulk
threads: 16
memory_gb: 32

# --- single_cell -------------------------------------------------------------
clustercatcher_run_dir: "/path/to/clustercatcher_results"
cellranger_dir: "/path/to/clustercatcher_results/cellranger"
samples: null                      # null reads sample_id from the AnnData

barcode:
  min_join_rate: 0.40              # measure with inspect-barcodes, then pin
  on_unmapped: "drop"              # drop | raise

vdj:
  require_productive: true
  require_paired: false
  min_umis: 2

# --- bulk --------------------------------------------------------------------
# sample_info: "/path/to/samples.pkl"
# trust4:
#   imgt_reference: "resources/IMGT+C.fa"
#   min_abundance: 2
#   chains: ["TRA", "TRB"]

# --- shared backend ----------------------------------------------------------
repertoire:
  diversity_methods: ["chao1", "shannon", "gini"]
  top_n_clones: 20

expansion:
  contrast: null                   # null for descriptive output only
  # contrast:
  #   group_col: "condition"
  #   test: "mutant"
  #   reference: "wildtype"
  #   exclude: "empty_vector"
  #   block_col: "donor"
  fdr: 0.05
  expansion_threshold: 0.01

specificity:
  method: "tcrdist3"
  radius: 50
  reference_dbs: ["vdjdb", "mcpas"]

modules:
  repertoire: true
  expansion: true
  specificity: true
  integration: true                # single_cell only
```

## Troubleshooting

#### Zero join rate in `single_cell` mode

The namespace tripwire fired. Run the diagnostic:

```bash
CloneCatcher inspect-barcodes --run-dir /path/to/clustercatcher_results --sample HPV01
```

Most often the ClusterCatcher run predates the barcode fix, or `sample_id` in the AnnData differs from the `cellranger multi` directory name. The diagnostic prints both and compares them.

#### Low but nonzero join rate

Expected, within limits. VDJ libraries recover T cells that GEX QC removes. Below roughly 30% suggests a key problem rather than QC attrition. Check `tcr/barcode_join_report.tsv` for the per-sample breakdown before lowering `min_join_rate`.

#### No expanded clones called

Check that `expansion_threshold` suits your depth. In bulk co-cultures a precursor clone can sit well below 1%. Lower the threshold or raise input cells.

#### Immunarch fails to load

Both environments carry R and Python together, so a failure here usually means the environment never solved rather than that R is missing. Build it explicitly and read the solver output:

```bash
snakemake --use-conda --conda-create-envs-only --configfile config.yaml
conda env list | grep CloneCatcher
```

If `tcrdist3` and `scanpy` conflict on `pandas` or `numpy`, pin them down rather than up. Both work on the `pandas 1.5` line; `tcrdist3` is the one that breaks on `pandas 2.x`.

#### TRUST4 finds few contigs

Confirm the libraries are 5' chemistry. TRUST4 cannot reconstruct receptors from 3' data, where the V region is not sequenced.
